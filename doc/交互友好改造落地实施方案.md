## 三、阶段 A —— 纯前端落地

### A1. 写信附件上传

- **前置验证（必做）**：发一封带附件的测试邮件，确认主进程 `sendMessage` 已消费 `ComposeMail.attachments`（契约已在 `types/index.ts` 定义）。若未支持，此项转阶段 B。

**改动：`Compose.tsx`**

```ts
// 新增类型（组件内局部类型）
interface LocalAttachment {
  filename: string;
  size: number;
  contentType: string;
  content: ArrayBuffer;
}

const [attachments, setAttachments] = useState<LocalAttachment[]>([]);
const fileRef = useRef<HTMLInputElement>(null);

const handleFiles = (e: React.ChangeEvent<HTMLInputElement>) => {
  const files = Array.from(e.target.files || []);
  e.target.value = ''; // 允许重复选择同一文件
  files.forEach((f) => {
    const reader = new FileReader();
    reader.onload = () =>
      setAttachments((prev) => [
        ...prev,
        { filename: f.name, size: f.size, contentType: f.type, content: reader.result as ArrayBuffer },
      ]);
    reader.onerror = () => addToast(`读取失败：${f.name}`, 'error');
    reader.readAsArrayBuffer(f);
  });
};
```

- `handleSend` 中：
```ts
const mail: ComposeMail = {
  // ...现有字段
  attachments: attachments.length
    ? attachments.map(({ filename, content, contentType }) => ({
        filename, content, contentType: contentType || undefined,
      }))
    : undefined, // 无附件时保持旧行为
};
```
- UI：工具栏「添加附件」按钮（`Paperclip`，`onClick={() => fileRef.current?.click()}`）+ 隐藏 `<input type="file" multiple ref={fileRef} onChange={handleFiles} className="hidden" />`；正文上方渲染附件列表（复用 `AttachmentBar` 样式风格，每项带「移除」按钮）。
- **验收**：选择多文件 → 列表显示名称/大小 → 可单个移除 → 发送成功 → 无附件时字段为 `undefined`。

### A3. 阅读区「上一封 / 下一封」导航

**改动 1：`utils/mailFilter.ts`（新建）** —— 消除过滤口径重复

```ts
import type { MailMeta } from '../types';
export type MailFilter = 'all' | 'unread' | 'read';

export function applyMailFilter(list: MailMeta[], filter: MailFilter, isSearching: boolean): MailMeta[] {
  if (isSearching) return list;
  if (filter === 'unread') return list.filter((m) => !m.seen);
  if (filter === 'read') return list.filter((m) => m.seen);
  return list;
}
```

- `MailList.tsx` 中 `MailFilter` 类型改为从 `utils/mailFilter` 导入（删除组件内定义），`visibleMessages` 改用 `applyMailFilter`，使 ToolPanel 与 MailList 共用同一份过滤结果，导航顺序不会错位。

**改动 2：`ToolPanel.tsx`**

```ts
const isSearching = activeSearchQuery.trim().length > 0;
const visibleMessages = useMemo(

const detailIndex = activeDetail
  ? visibleMessages.findIndex((m) => m.uid === activeDetail.uid &&
      (!isUnified || m.accountId === activeDetail.accountId))
```

- 向 `MailReader` 传入 `onPrev` / `onNext`（各取 `visibleMessages[detailIndex - 1 / + 1]` 后 `onSelect`）及 `hasPrev` / `hasNext`。

**改动 3：`MailReader.tsx`** —— 头部工具区新增两个图标按钮（`ChevronUp` / `ChevronDown` 或 `ArrowUp` / `ArrowDown`），首/尾禁用（`disabled={!hasPrev}` 等）。

### A4. 列表键盘导航（Gmail 风格）

**改动 1：`utils/dom.ts`（新建）**

```ts
export function isTypingTarget(el: EventTarget | null): boolean {
  const node = el as HTMLElement | null;
  if (!node) return false;
  const tag = node.tagName;
  if (tag === 'INPUT' || tag === 'TEXTAREA' || tag === 'SELECT') return true;
  return node.isContentEditable === true;
}
```

**改动 2：`MailList.tsx`**

```ts
const [activeIndex, setActiveIndex] = useState(-1);
const listRef = useRef<HTMLDivElement>(null);

const onKeyDown = (e: React.KeyboardEvent) => {
  if (isTypingTarget(e.target)) return;   // 输入框/富文本聚焦时不劫持
  if (selectionMode) return;              // 多选模式禁用方向键（语义冲突）
  const n = visibleMessages.length;
  if (n === 0) return;
  switch (e.key) {
    case 'j': case 'ArrowDown': e.preventDefault(); setActiveIndex((i) => Math.min(n - 1, i + 1)); break;
    case 'k': case 'ArrowUp':   e.preventDefault(); setActiveIndex((i) => Math.max(0, i - 1)); break;
    case 'Enter': if (activeIndex >= 0) onSelect(visibleMessages[activeIndex]); break;
    case 'Delete': case 'Backspace': if (activeIndex >= 0) onDelete(visibleMessages[activeIndex]); break;
    case 'n': onCompose(); break;
  }
};
```

- 容器 `div` 加 `tabIndex={0}` 与 `onKeyDown={onKeyDown}`；每行加 `data-mail-index={i}`，点击行 `onSelect` 时同步 `setActiveIndex(i)`。
- 滚动跟随（`useEffect` 依赖 `activeIndex`）：
```ts
listRef.current?.querySelector(`[data-mail-index="${activeIndex}"]`)?.scrollIntoView({ block: 'nearest' });
```
- `activeIndex === i` 时给行加 `bg-accent/50`（与 `selectedUid` 高亮同色叠加）。
- `visibleMessages` 变化时 `setActiveIndex(-1)` 复位（`useEffect` 依赖 `visibleMessages`）。

- **验收**：J/K 上下移动并高亮、Enter 打开、Delete 删除、N 写信；焦点在搜索框/写信正文时按键不被拦截；多选模式方向键不误触。

### A5. 草稿自动保存

**改动：`Compose.tsx`**

```ts
const [draftId, setDraftId] = useState<string | null>(draft?.id ?? null);
const skipFirstRef = useRef(true); // 打开草稿的首次渲染不重写

useEffect(() => {
  if (skipFirstRef.current) { skipFirstRef.current = false; return; }
  if (sending) return;
  const t = window.setTimeout(() => {
    const d: Draft = {
      id: draftId ?? generateId('draft'),
      accountId: account.id,
      to, cc, bcc, subject: subject.trim(), bodyHtml,
      updatedAt: Date.now(),
    };
    draftService.upsertDraft(d);
    setDraftId(d.id);
    savedRef.current = snapshot(); // 与 A2 脏检测联动
  }, 2000);
  return () => window.clearTimeout(t);
}, [to, cc, bcc, subject, bodyHtml, sending]);
```

- 与手动「存草稿」共用 `draftService.upsertDraft`，不另建存储。
- 发送成功后按 `draftId` 删除草稿（兼容自动生成的 id）。
- **验收**：输入后 2s 自动写入；草稿箱出现自动草稿；发送后自动草稿被删除；不产生重复草稿条目。

### A8. 邮箱格式校验

**改动 1：`utils/validate.ts`（新建）**

```ts
export function splitAddresses(s: string): string[] {
  return s.split(/[,;]/).map((x) => x.trim()).filter(Boolean); // 兼容逗号/分号分隔
}
export function isValidEmail(s: string): boolean {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(s);
}
```

**改动 2：`Compose.tsx`**
- `handleSend` 前校验：
```ts
const invalid = [...splitAddresses(to), ...splitAddresses(cc), ...splitAddresses(bcc)]
  .filter((a) => !isValidEmail(a));
if (invalid.length) { addToast(`存在无效邮箱地址：${invalid.join('、')}`, 'warning'); return; }
```
- `to` / `cc` 的发送字段改用 `splitAddresses(...)` 替换原有 `to.split(',').map(...)` 内联逻辑。

### A9. 远程图片按需加载（隐私友好）

**改动：`MailReader.tsx`**

```ts
const [showRemote, setShowRemote] = useState(false);
// detail 变化时复位
useEffect(() => setShowRemote(false), [detail?.uid]);

const cleanHtml = useMemo(() => {
  if (!detail?.html) return '';
  if (!showRemote) {
    return DOMPurify.sanitize(detail.html, {
      FORBID_TAGS: ['img', 'iframe', 'script', 'style', 'link', 'video', 'audio', 'object', 'embed'],
      FORBID_ATTR: ['src', 'srcset', 'style', 'onclick', 'onerror', 'onload'],
    });
  }
  return DOMPurify.sanitize(detail.html, {
    FORBID_TAGS: ['iframe', 'script', 'style', 'link', 'video', 'audio', 'object', 'embed'],
    FORBID_ATTR: ['style', 'onclick', 'onerror', 'onload'],
    ALLOWED_URI_REGEXP: /^(?:https?:|mailto:|tel:)/i, // 仅放行 http/https 图片
  });
}, [detail?.html, showRemote]);
```

- `const hasImg = /<img\b/i.test(detail?.html || '')`。
- 当 `hasImg && !showRemote` 时显示「显示图片」按钮，点击 `setShowRemote(true)`。
- iframe 的 `srcDoc={cleanHtml}` 随 cleanHtml 变化自动重渲染，无需额外处理。
- **安全红线**：放行后 `script/iframe/object/embed` 仍禁、URI 白名单仅 http/https/mailto/tel，禁 `data:` / `javascript:`。
- **验收**：默认不加载图片；点「显示图片」后图片出现；含 `<script>` 的邮件仍不执行；切换邮件后复位为不加载。

## 四、阶段 B —— 需主进程小扩展

> 前端改动可先写（字段为可选，兼容 `undefined`），主程序 `emailService.cjs` 同步返回新字段后即可生效。

### B1. 星标邮件（\Flagged）

- **主进程改动**：`listMessages`（及 `getMessage`）返回对象新增 `flagged: boolean`。
- **前端改动**：
  1. `types/index.ts` `MailMeta` 加 `flagged?: boolean;`
  2. `useMailStore` / `useUnifiedStore` 新增 `toggleFlag(uid, flagged)`：调 `emailService.setFlags({ ..., add, flags: ['\\Flagged'] })`（**复用现有 setFlags，无需新增 IPC**），成功后更新 `messages` 中对应项 `flagged`。
  3. `MailList` 行内加星标图标（`Star`，`fill` 随 flagged 切换），点击 `toggleFlag`（`stopPropagation`）。
- **验收**：点星标即时切换并持久化；刷新后状态保留；不破坏已读/未读标记。

### B2. 列表摘要（snippet）

- **主进程改动**：`listMessages` 返回 `snippet: string`（正文前 ~80 字纯文本，**避免 fetch 全量正文**——用轻量方式提取，或首次打开详情后回填缓存）。
- **前端改动**：`MailMeta` 加 `snippet?: string;`；`MailList` 行内主题下方灰显单行 `m.snippet`（`truncate`）。
- **验收**：列表层可见内容摘要；不显著增加列表加载耗时。

## 六、回归测试清单

1. 账号切换 / 凭据解密链路不回归（A 阶段不触碰 store 数据流）。
2. 统一收件箱 vs 单账号视图的 `isUnified` 分派逻辑不被新交互破坏。
3. 搜索态 / 多选态 / 未读筛选态下，导航（A3）与筛选（A11）口径一致。
4. 键盘导航（A4）不得劫持搜索框、写信正文、账号表单的按键。
5. 远程图片开关（A9）不突破 DOMPurify 安全边界（`script`/`iframe`/`data:` 始终拦截）。
6. 发送链路（A1/A7/A8/A5）在「无附件、无 Bcc、无非法地址」时行为与改动前完全一致。
